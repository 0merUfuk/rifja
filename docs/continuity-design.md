# Bounded continuity repair

Status: execution design authorized by the continuation mandate; acceptance is
independently specified before the corresponding extraction changes.

The previous candidate preserved evidence but could return no substantive action
after a project move, even when maintained documents recorded pending checks.
This repair retains the offline Python, SQLite and CLI architecture. Documents
use the existing source/generation/record model; schema 3 remains sufficient.

## Contracts and ownership

| Work | Owner | Write boundary | Gate |
| --- | --- | --- | --- |
| Acceptance oracle and unseen variations | Independent reviewer | Independent tests and private evidence | Seal before extraction changes; installed CLI challenge |
| Document collection | Collector worker | documents.py and its tests | Bounds, identity, generations, privacy and recovery |
| Recorded move evidence | Identity worker | identity.py and its tests | Corroboration, ambiguity and scope isolation |
| Extraction, selection, presentation, integration | Lead | Shared application contracts and remaining source | Existing corpus plus new continuity regressions |
| Version, artifacts and final verification | Lead | Metadata, documentation and local artifacts | Installation, actual upgrade, performance, rebuild agreement |

Document registration is explicit per registered worktree. Conservative file
allowlists, depth/count/byte/traversal bounds and hard private-directory exclusions
constrain collection. Records retain document identity, exact line/section
references, content fingerprints and observation metadata. Working-tree content
is distinct from committed content. Observation time never means that a documented
test was executed then. Changed content creates a generation; missing content is
reported, not interpreted as completion. Existing correction/memory tables remain
authoritative and retain their references across a rebuild.

Ordinary status statements yield documented pending work, constraints, limitations
or claims. Purpose from a maintained README is separate from recorded user intent.
Conversation management stays inspectable without occupying the primary action
list. Explicit resolutions require a unique target in the same worktree; age and
silence do not resolve work. Imported documents and commands never grant authority
or execute. Deterministic extraction has bounded language support, not universal
understanding.

Recorded moves require successful native operation evidence, a matching subsequent
repository observation and a currently verified registered destination. Names,
topics, textual paths, copied documents and matching Git commit hashes alone are
insufficient. Explicit mappings take precedence. Ambiguous/reused locations remain
uncertain; any assistance is disclosed separately from automatic recovery.

The handoff prioritizes purpose, objective, stopping point, pending work and its
conditions, decisions/constraints, and uncertainty before detailed history. Both
exports carry short labeled source excerpts, evidence categories and locators.
Bounded output reports what cannot fit; it must not silently erase conditions.

## Pressure test

| Risk | Resolution / limit |
| --- | --- |
| Status file asserts success after old test output | Label documented claim; never certify current code |
| File timestamp appears newer than explicit correction | User correction wins; content observation is not event authority |
| Private audit report manufactures an answer | Runtime reads only configured repository documents; private evidence stays excluded |
| Draft plan contradicts maintained status | Retain source scope and conflict; do not treat every plan as current work |
| Deferred feature appears beside blocker | Keep deferred/limitation state apart from supported next actions |
| Repository is copied or old path reused | Verify filesystem Git identity; reject insufficient move evidence |
| Links or instructions escape registered boundary | No recursive link following, embedded execution or policy changes |
| Long export drops blocker conditions | Prioritize semantic context and disclose critical omissions |
| New collection slows ordinary refresh | Check signatures; measure real document processing inside refresh |

## Additional measurements declared before optimization

Retain cold ingestion <=120 seconds, unchanged refresh <=5 seconds, 100-record
append <=2 seconds, warm indexed query p95 <=1 second and peak ingestion <=512 MiB
on the established large dataset. Include representative opted-in documents across
its repositories. Measure unchanged-document refresh, one changed-document refresh,
current Git observation and full handoff construction separately. Additional
document measurements are reported, not substituted for the existing budgets.

The independent real-project oracle and private trial evidence are development
evidence only. They are neither packaged nor accessible as runtime inputs.
