## Discovery and explicit scope

Use explicitly configured roots first. Suggested defaults are `$CODEX_HOME` or `~/.codex`, `$CLAUDE_CONFIG_DIR` or `~/.claude`, and `$HERMES_HOME` or `~/.hermes`; suggest them without silently importing. Hermes profiles may have separate `<root>/profiles/<name>/state.db` stores; an explicit profile directory avoids guessing the active profile. Only enumerate transcript-specific subtrees. Do not inspect authentication, environment, logs, memory, or arbitrary config values.

Codex documents its state-home override in [advanced configuration](https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations). Claude documents the transcript path, `CLAUDE_CONFIG_DIR`, the optional `CLAUDE_CODE_PROJECT_DIR_NAME`, persistence controls, and retention in [session storage](https://code.claude.com/docs/en/sessions#where-transcripts-are-stored). The project directory spelling is not a reliable cwd: it is lossy and can be explicitly overridden. [Subagent documentation](https://code.claude.com/docs/en/sub-agents#resume-subagents) identifies separate subagent transcripts.

A missing executable does not make a store unavailable. An installed executable does not prove that a transcript uses that executable's version. Unknown signatures, inaccessible roots, unsupported compression, and missing stores are explicit diagnostics.

## Codex

The pinned [SessionMeta definition](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/protocol/src/protocol.rs) defines `id` as the task/thread identity and `session_id` as the root-thread grouping identity. Older records may omit `session_id`. A rollout starts with `{timestamp, type: "session_meta", payload: {id, timestamp, cwd, cli_version, ...}}`; modern records add `ordinal`. Use the first valid header for identity. Fork files can contain additional inherited parent headers: those must never switch the current identity. Preserve `parent_thread_id`, `forked_from_id`, `history_base`, and `subagent_history_start_ordinal` when supplied. The latter explicitly excludes earlier inherited context from the child's projected conversation. Linked history bases are reported as incomplete external lineage rather than recursively followed beyond configured scope.

`response_item.payload.type == "message"` contains `role` and `content`; `input_text`/`output_text` parts contain `text`. Roles include user, developer, system, and assistant. `phase` is optional and cannot prove completion. `agent_message` contains `author`, `recipient`, and content parts; encrypted content is opaque. Function and custom tool calls contain `call_id`, tool name, and arguments/input. Tool outputs contain `call_id` and `output`, which is a string or structured parts. The pinned [response definitions](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/protocol/src/models.rs#L978) establish these shapes.

`event_msg.payload.type` describes events including `task_started`, `task_complete`, `turn_aborted`, `token_count`, and `item_completed`; completed items can carry command, cwd, exit_code, and output. Completion is historical producer state, never verification of current code. Mirrored user/assistant event text is metadata where response items already carry the conversation. `turn_context.cwd` updates association; event-level cwd overrides it. Preserve supplied git branch/commit metadata without inferring dirty state. Times are ISO strings; retain source precision and resolve awareness at the application boundary. File order/ordinal establishes sequence.

Observed other kinds include `world_state`, `token_usage_record`, `inter_agent_communication_metadata`, and `compacted`. These establish known metadata coverage but are not user intent. Encrypted reasoning and model context are not treated as user claims. Unknown kinds remain diagnosable. Compacted replacement history must not be blindly re-imported as newly authored messages.

The pinned [rollout writer](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/rollout/src/recorder.rs) appends newline-delimited records and flushes asynchronously. Defer an incomplete final line, tolerate malformed middle lines with diagnostics, and detect truncation/replacement. Archive moves preserve identity. [Rollout filenames](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/rollout/src/rollout_file_name.rs) may add a rollout identity suffix after revert; file basenames are provenance, not canonical identity. [Compression source](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/rollout/src/compression.rs) supports `.jsonl.zst`. The implemented reader uses Python 3.14's standard-library Zstandard decoder: maximum compressed input 256 MiB, maximum decompressed output 256 MiB, 8 MiB decoder history window, 1 MiB per record, bounded read/output chunks, and a 30-second cooperative deadline per source. The deadline is checked between decoder/reader calls and includes consumer processing; it is not a hard operating-system interruption guarantee. Invalid/truncated frames, oversized windows, dictionaries, time and size limits produce bounded diagnostics. An unchanged sealed archive skips decompression; a changed archive replays that one file as a new source generation. No genuine `.jsonl.zst` files were available locally, so native-source and synthetic verification remain distinct from a genuine compressed-file check. Codex `history.jsonl`, state indexes, and task SQLite metadata are not substitutes for full rollout records.

## Claude Code

A conversation record has `type` user/assistant, `uuid`, `sessionId`, `timestamp`, `cwd`, `parentUuid`, and `message: {role, content}`. Content is a string or parts. Text parts have `{type: "text", text}`; assistant tool invocations have `{type: "tool_use", id, name, input}`; user-envelope tool results have `{type: "tool_result", tool_use_id, content, is_error}`. A tool result inside a user envelope is historical tool evidence, not user intent. Preserve UUID and block index for identity and `parentUuid` for ancestry. Subagent records additionally have `agentId` and often `isSidechain`; combine parent session ID and agent ID so the child does not merge into its parent.

Known metadata includes attachment, progress, system, queue-operation, last-prompt, custom-title, atis-latch, mode, bridge-session, agent-name, summary and file-history-snapshot. System `subtype: compact_boundary` marks compaction. Thinking blocks are not user-facing assertions. `isMeta` and `isCompactSummary` user records are context metadata; do not extract them as fresh tasks. `toolUseResult` can supply exit status, but `is_error` alone must not invent a numeric exit code. Cwd and gitBranch are historical metadata; the encoded parent folder must never supply project identity.

Claude explicitly warns that raw transcript entry formats are internal and can change each release. Support is shape-checked and partial coverage is visible. Append offsets work for simple additions; parent links, branch/rewind behavior and compaction do not justify claiming the raw file is the current active conversation. Preserve raw historical ancestry and mark this limit instead of reconstructing an unverified resume chain. Retention/deletion and disabled persistence can produce incomplete history. JSONL needs no WAL handling.

## Hermes

The installed producer defines the relational format in `hermes_state_common.py`, `SCHEMA_VERSION = 26`, `SCHEMA_SQL`, `sessions` and `messages`. Discover a database by SQLite header plus the required sessions/messages columns, not filename alone. The reader accepts ordinary `CREATE TABLE` definitions for `sessions`, `messages`, and an optional `schema_version` table. It rejects views and virtual tables before reading their row content. `sessions.id` is identity; `parent_session_id` captures lineage. `started_at`, `ended_at`, and `messages.timestamp` are Unix seconds (REAL). Metadata may include cwd, git_repo_root, git_branch, source, archived, hidden, and end_reason. Missing cwd is unresolved, not inherited from the collector's working directory. No PATH executable was available, so package/source evidence establishes this implementation rather than an invented executable version.

Required message fields: `id` INTEGER primary key, `session_id`, `role`, `content`, `timestamp`. Optional fields include `tool_calls` JSON, `tool_call_id`, `tool_name`, `active`, `compacted`, `_compressed_summary`, `display_kind`, and `display_metadata`. Assistant `tool_calls` is a list with `id`/`call_id`, `type`, and `function: {name, arguments}`. Tool rows match `tool_call_id`. User/assistant/tool roles were observed. The content codec in `hermes_state.py:_encode_content/_decode_content` uses the literal NUL-prefixed sentinel `\x00json:` for structured values. Ordinary JSON-looking text remains plain text. Do not parse every JSON-looking content string as structured conversation.

Use `ORDER BY messages.id`; the producer deliberately avoids timestamp ordering because wall clocks can regress. The display set is `active=1 OR compacted=1`, while rewind rows `active=0 AND compacted=0` remain excluded. Older schemas without those optional columns default to all rows visible. In-place compaction may copy the protected tail into new rows. The producer deduplicates role/content/timestamp/tool_call_id/tool_calls/tool_name, preferring active then greatest id. A content hash can represent this key without retaining extra private text. User summary carriers can need producer-specific text unwrapping; do not claim full UI-equivalent projection for those, and keep a compaction diagnostic when present.

Read the live DB with SQLite URI `mode=ro`, `PRAGMA query_only=ON`, `PRAGMA trusted_schema=OFF`, and a read transaction so the main DB and WAL form one consistent snapshot. Never use `immutable=1` on a live WAL database, never copy only the main file, and never checkpoint/migrate/repair the source. Do not instantiate the producer's SessionDB constructor: it performs maintenance. Refresh change detection must include DB and WAL file state; edits to active flags require rereading changed stores, not solely id-based appends. Hermes supports WAL and filesystem-dependent rollback modes; neither makes a missing WAL safe to ignore.

Each reader connection has a cooperative budget of approximately 100 million SQLite VM instructions or 30 seconds from opening, checked every 1,000 VM instructions. SQLite interruption produces an explicit source diagnostic. This is not an operating-system deadline and cannot interrupt stalled I/O between progress callbacks. `PRAGMA cache_size=-8192` requests an approximately 8 MiB SQLite page cache; it is not a bound on total process memory. Large-store throughput and completion within these limits require separate measurement.

The producer also has JSON/JSONL portability and emergency spill files under sessions, but those can be incomplete or duplicate SQLite content. This release imports the verified SQLite format only; an explicit diagnostic covers unsupported Hermes exports/spools. Archived is lifecycle metadata, not proof of inactivity or completion. Ended sessions may remain resumable.

## Verification boundary

Research used executable version checks, aggregate field-shape inspection of bounded genuine samples, read-only schema/count queries, and pinned producer source. No genuine messages, account identifiers, credentials, config values, or personal absolute paths belong in distributable fixtures or this report. Adapter tests use synthetic examples for contract behavior; private real-data smoke checks separately establish that actual installed stores parse. Neither synthetic tests nor producer completion events certify the current repository.
